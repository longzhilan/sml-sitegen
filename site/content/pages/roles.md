## 三层权限，互不相干

这个站点有三处权限，**互相独立**：群里的身份（QQ 群管理）不等于仓库权限，仓库权限不等于 CF Pages 发布权限。

| 角色 | Gitee 仓库（权威源） | GitHub（只读镜像 + 构建） | Cloudflare Pages（发布） |
|---|---|---|---|
| 群主 CXi | Owner：可改一切、可任免管理员 | — | — |
| 管理员（多名） | Developer：可合并 PR、建分支、改契约与配置 | — | 发布权限（持有 API Token 者） |
| 贡献者 | Developer（累计 3 篇通过后授予） | — | — |
| 群友 | 无写权限：fork + PR，或交给管理员代投 | — | — |
| 机器人 / CI | — | Actions 用仓库自带 `GITHUB_TOKEN` | 由 Actions 用 Token 发布 |

原则：**给最小够用的权限**。GitHub 侧原则上不给人写权限——它是镜像，只由 CI 更新；CF Pages 的 Token 只放在 GitHub Secrets 与管理员本地。

## 谁可以做什么

- **改内容**（文章、文档页、词条、成员档案、资源、周报）：所有人走 PR；贡献者可直接建分支提 PR；管理员可直接合并。
- **改制度与规范**：只有管理员。制度改动必须在 PR 描述里写明「改了哪条、为什么」。
- **改契约**（`site/content/contracts/*.sml`）：只有管理员。契约一改，所有人的校验规则与站文档会同时变，必须单开 PR。
- **改引擎**（`engine/`）与站点配置（`site/content/site.sml`）：只有管理员。
- **发布与回滚**：管理员。回滚步骤见 `docs/DEPLOY.md`。

## 成为贡献者（拿写权限）

1. 以 PR 形式提交并通过 ≥ 3 篇内容（文章或文档页）；
2. 在群里向任意管理员提出申请，说明想长期参与的方向；
3. 管理员两人以上无异议即授予仓库 Developer 权限；
4. 记录在案（成员档案里 `role` 字段更新）。

## 权限回收

出现下列情形之一即回收写权限，并在群里说明理由：连续 6 个月无有效贡献且本人同意回收、恶意提交、绕过审核直推 master、泄露站点密钥、严重违反内容边界。

## 代投与署名

管理员代投时必须保留原作者署名（`author` / `co_authors` 字段），并在 PR 描述里注明「代投，原作者 @某群成员」。代投不改变版权归属。

## 决策方式

- 日常事务：任一管理员可决定。
- 制度变更、权限授予/回收、下架争议：**两名以上管理员同意**。
- 分歧无法收敛时，在群里公开说明两方理由，由群主裁决。
